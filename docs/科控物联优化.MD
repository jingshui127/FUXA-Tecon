### 2.2 插件安装方式（当前版本）

当前版本优先通过 FUXA 网页的插件管理页面安装通讯插件：

```text
http://127.0.0.1:1881/plugins
```

安装后的插件由运行时服务保存到 EXE 同目录：

```text
<EXE目录>\data\_pkg\runtime\node_modules\
```

因此，以下依赖不需要再手工添加到 `server/package.json` 或 `fuxa-headless/package.json`，也不需要在构建前重复执行 `npm install`：

- `modbus-serial`
- `node-snap7`
- `node-opcua`
- `node-bacnet`
- `ads-client`

迁移到其他电脑时，将 EXE 和完整的 `data\` 文件夹一起复制即可保留已安装插件。只有在以下情况才需要手工加入构建依赖：

1. 插件必须在 EXE 内置、不能通过网页安装；
2. 插件代码在 FUXA 启动初始化阶段就被静态 `require`；
3. 目标环境无法联网安装插件；
4. 原生插件需要针对目标 Node.js ABI 重新编译。

**安装命令（历史方案，仅用于旧版本或离线构建，不是当前推荐方式）：**
```bash
cd server
npm install modbus-serial@8.0.19 node-snap7@1.0.9 node-opcua@2.149.0 node-bacnet@0.2.4 ads-client@2.1.0
```

## 七、运行说明

### 7.1 开发模式
```bash
cd ./server
npm start
```
访问: http://localhost:1881

### 7.2 Headless 模式
双击运行 `fuxa-pro-headless.exe`。

默认访问地址：

```text
http://127.0.0.1:1881/
```

Node-RED：

```text
管理编辑器：http://127.0.0.1:1881/flows
兼容入口：http://127.0.0.1:1881/nodered
Dashboard：http://127.0.0.1:1881/dashboard
```

如果访问 `/flows` 返回 `Cannot GET /flows`，说明 Node-RED 尚未成功初始化，应先检查启动日志中的 `[Node-RED]` 错误详情。

### 7.3 数据存储位置

数据存储在 **EXE 同目录下的 `data` 文件夹**：

```text
fuxa-pro-headless.exe
└─ data\
   ├─ _pkg\runtime\node_modules\   # 网页安装的插件
   ├─ node-red\flows.json          # Node-RED 流程
   ├─ project.prjstorage            # FUXA 项目
   └─ 其他运行数据和日志
```

复制 EXE 到其他 Windows x64 电脑时，应连同整个 `data\` 文件夹一起复制；这样通常不需要重新安装 Node-RED、node-snap7 等网页安装插件。

## 九、注意事项

1. **S7 插件兼容性：** 必须使用 Node 18 环境，Node 20 可能导致原生模块加载失败
2. **Headless 打包：** 必须使用完整的 `--public-packages` 参数暴露原生模块：
   ```
   --public-packages "node-snap7,bindings,nan,@serialport/bindings-cpp"
   ```
3. **构建流程：** 推荐使用 GitHub Actions 自动构建，避免本地环境问题
4. **数据存储：** Headless EXE 首次运行会自动创建同级 `data\` 目录；不要把 `data\`、`artifacts\` 或临时测试目录提交到 Git
5. **编码错误修复：** 已修复 fontkit 编码问题（将 `ascii` 改为 `utf-8`），字体标签正常显示
6. **Stardust 遥测：** 已禁用 APM 遥测服务，避免连接失败产生错误日志
7. **文件上传/下载：** 已修复 pkg 快照限制问题，小部件上传下载功能正常
8. **端口占用：** 确保 1881 和 8080 端口未被占用，否则启动失败

## 十、核心代码修改记录

### 10.1 headless-start.js（入口文件）
- **路径**: `server/headless-start.js` / `fuxa-headless/server/headless-start.js`
- **作用**: 获取 exe 所在目录，创建数据目录，启动服务器
- **关键修改**: 使用 `process.execPath` 获取 exe 位置，传递 `execDir` 给 main.js

### 10.2 main.js（主程序）
- **路径**: `server/main.js` / `fuxa-headless/server/main.js`
- **关键修改**:
  - `settings.appDir = __dirname` 保留：pkg 中它指向内置服务源码快照，Node-RED 集成必须从此路径加载内部模块；可写数据仍由 `rootDir`、`workDir` 和 `packageDir` 管理
  - Headless Server 模式将 EXE 同级 `data\` 设置为 `userDir`
  - Stardust `enabled: false`（禁用遥测）

### 10.3 plugins/index.js（插件检测）
- **路径**: `server/runtime/plugins/index.js`
- **关键修改**: 增加 `require.resolve()` 多重路径检测逻辑

### 10.4 fontkit（字体处理）
- **路径**: `fuxa-headless/node_modules/fontkit/dist/main.cjs`
- **关键修改**: 第 5424 行 `TextDecoder('ascii')` → `TextDecoder('utf-8')`

### 10.5 package.json（打包配置）
- **路径**: `fuxa-headless/package.json`
- **关键配置**:
  ```json
  {
    "bin": "main.js",
    "pkg": {
      "assets": [
        "server/**/*",
        "node_modules/**/*",
        "client/dist/**/*",
        "_reports/**/*"
      ],
      "publicPackages": ["bindings", "@serialport/bindings-cpp"],
      "compression": "None"
    }
  }
  ```
- 根目录 `node_modules` 只保留一份，避免重复扫描；不使用旧的 Brotli/GZip 压缩配置。

## 十一、FUXA 自动化技能

本项目集成了 FUXA-Automation 技能，支持通过 AI Agent 远程配置和管理 FUXA 系统。

### 11.1 技能文件位置

```
.trae/skills/fuxa-automation/
├── SKILL.md                    # 技能定义文件
└── references/
    ├── alarm-template.json     # 报警模板
    ├── config-template.json    # 配置模板
    ├── data-models.md          # 数据模型文档
    ├── device-template.json   # 设备驱动模板
    ├── fuxa-cli.js            # REST API 客户端
    └── script-template.js     # 脚本模板
```

### 11.2 支持的功能

- **远程设备配置** — 支持 16 种工业协议（Modbus TCP/RTU、S7、OPC UA、MQTT 等）
- **标签读写** — 实时读取/写入设备标签值
- **报警管理** — 多级报警配置、通知、确认
- **组态配置** — 视图、布局、数据绑定
- **脚本生成** — 服务端 JavaScript 脚本
- **历史数据查询** — DAQ 数据检索

### 11.3 使用示例

```javascript
const { FUXAClient } = require('./references/fuxa-cli');

const client = new FUXAClient({
  url: 'http://192.168.1.100:1881',
  apiKey: 'your-api-key'
});

// 获取设备列表
const devices = await client.getDevices();

// 创建 Modbus TCP 设备
await client.setDevice({
  id: 'd_modbus_01',
  name: 'Modbus PLC',
  type: 'ModbusTCP',
  property: { address: '192.168.1.100', port: '502', slaveid: '1' },
  tags: { 't_temp': { id: 't_temp', name: '温度', type: 'Float32', memaddress: '400001' } }
});

// 读取标签值
const values = await client.getTagValue(['t_temp']);
```

### 11.4 关键提醒

- Modbus 从站 ID 字段名是 `property.slaveid`（全小写字符串）
- 设备地址字段名是 `property.address`
- 语言代码是 `zh-cn`（不是 `zh`）
- projectData cmd 值是 `'set-device'`、`'set-alarm'`

## 十四、2026-06-26 全面修复记录

本次参考 `FUXA定制化优化指南.md` 共修复 8 项：

### 14.1 main.js PORT 环境变量支持
- **文件**: `server/main.js`
- **修复**: 添加 `process.env.PORT` 读取，优先级: CLI -p > PORT 环境变量 > mysettings.json > 默认 1881
- **原因**: pkg EXE 不支持 CLI args 透传，Guardian 需通过环境变量传递端口

### 14.2 fontkit 懒加载修复
- **文件**: `server/api/resources/index.js`
- **修复**: `const fontkit = require('fontkit')` 改为 `var fontkit` 懒加载 + `if (!fontkit) { fontkit = require('fontkit'); }`
- **原因**: pkg 打包后 fontkit 顶层 require 触发 `windows-1252 encoding not supported` 崩溃

### 14.3 S7 驱动完整修复
- **文件**: `server/runtime/devices/s7/index.js`
- **修复内容**:
  - `disconnect()` 移除 `s7client.Disconnect()` 调用，仅清理 JS 侧状态
  - `_checkWorking()` overload >= 3 时将 `s7client = null`（不调用 Disconnect），强制全新重连
  - `process.on('exit')` 将 s7client 置 null，降低退出时 native 清理冲突
  - `_readDB()` / `_readVars()` 添加 `!s7client` 判空保护
  - `_getErr()` 添加 s7client 判空保护

### 14.4 视图保存免重启 + 异步重启
- **文件**: `server/runtime/project/index.js`, `server/api/projects/index.js`
- **修复**:
  - 新增 `getRawProject()` 无权限过滤的原始数据读取
  - 保存项目后先 `res.end()` 再异步重启
  - 比较 devices/server/alarms/notifications 四个关键字段，无变化跳过 restart
  - 日志输出 `api post project: views-only change, skip restart`

### 14.5 upload pkg mkdir 修复
- **文件**: `server/api/projects/index.js`
- **修复**: destination 路径优先使用 `process.env.userDir`（数据目录）而非 `settings.appDir`（pkg 只读快照）

### 14.6 设备 start/stop try-catch 保护
- **文件**: `server/runtime/devices/index.js`
- **修复**: `start()` 循环内添加 try-catch，单个设备崩溃不影响其他设备

### 14.7 guard.js 开发守护脚本
- **文件**: `server/guard.js`（新建）
- **用途**: 开发模式守护进程，用法 `cd server && node guard.js -p 1886`
- **特性**: 崩溃自动重启、冷却窗口保护、PORT 环境变量传递、启动信息含技术支持联系

### 14.8 日志前缀优化
- **文件**: `server/guard.js`, `app/headless/headless-guardian.js`
- **修复**: `[Guardian]` → `[TcScada]`，对普通用户更友好
- **启动信息**: 添加 `科控物联提供技术支持 | QQ: 2492123056`

### 14.9 Node-RED pkg 兼容性修复
- **文件**: `server/integrations/node-red/index.js`
- **修复**: `functionGlobalContext` 中的 `require()` 从 `settings.appDir` 改为基于 `__dirname` 的相对路径
- **原因**: pkg EXE 中 `appDir` = 数据目录 `data/`，代码在 snapshot 中，`require(appDir + 'runtime/...')` 报 MODULE_NOT_FOUND
- **解决**: `const serverDir = path.join(__dirname, '..', '..')` 动态计算 snapshot 路径

### 10.9 Node-RED `/flows` 入口与排查
- FUXA 默认配置弹窗中的 “Node-RED Flows” 图标继续使用 `/flows`，本次没有修改该前端跳转。
- Node-RED 管理编辑器由内置集成挂载到 `/flows`；`/nodered` 仅保留为兼容入口；`/dashboard` 用于 HTTP 节点和 Dashboard。
- `nodeRedEnabled` 最终读取 `<userDir>\_appdata\mysettings.json`，不是底层写死。关闭时不会挂载 `/flows`。
- 访问 `/flows` 返回 `Cannot GET /flows`，表示 Node-RED 尚未成功初始化或未启用；应先查看启动日志中的 `[Node-RED]` 错误，并等待出现 `[Node-RED] Started at /flows (dashboard: /dashboard)`。
- pkg 环境中 `__dirname` 是内置服务源码路径，`settings.appDir` 是可写数据配置时容易混淆；Node-RED 集成的内部模块路径必须基于 `__dirname` 计算，不能改用数据目录路径。

### 10.10 pkg 打包流程修复
- **文件**: `fuxa-headless/package.json`
- **修复**: 移除 `dependencies` 字段，robocopy 不排除 `node_modules`，依赖通过 `server/**/*` asset 自动打包
- **原因**: pkg 通过 asset 而非 npm dependencies 解析模块；之前的排除导致 dayjs 子模块缺失

### 14.11 SIGINT 优雅退出修复
- **文件**: `server/main.js`
- **修复**: 删除 `process.on('SIGINT')` 中的同步 `process.exit()`，将日志和退出移到 `FUXA.stop().then()` 回调中
- **原因**: 原代码 `FUXA.stop().then(...)` 后紧跟 `process.exit()` 同步退出，导致 `FUXA.stop()` 清理逻辑（设备断连、报警停止、脚本清理）从未真正执行
- **影响**: 低风险修复，OS 本身会回收资源，但优雅关闭更可靠

### 14.12 customization 外部化（支持 EXE 打包后换 LOGO）
- **文件**: `server/main.js`
- **修复内容**:
  - `getCustomization()`: 优先读 EXE 同级 `customization/config.json`，未找到则回退内置
  - 新增 `externalCustomizationDir` 变量（`path.join(execDir, 'customization')`）
  - 新增 `/assets/customization` express.static 路由，外部目录优先于内置
- **使用方式**: 在 EXE 同级创建 `customization/` 文件夹，放入 `config.json` / `logo.svg` / `favicon.ico` 即可覆盖默认品牌标识，不创建文件夹也不影响运行
