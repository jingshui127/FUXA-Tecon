# FUXA 客户定制化补丁系统

## 系统概述

本系统为 FUXA SCADA/HMI 项目提供了一套完整的客户定制化解决方案，支持为不同客户快速生成专属的补丁包。

## 核心组件

### 1. 基础补丁包 (tecon-patch)
包含所有定制化功能的基础文件：
- Stardust APM 集成
- 地图源优化
- S7 通讯插件
- GitHub Actions 配置
- FUXA 自动化技能

### 2. 配置模板 (config-template.json)
客户配置文件的标准格式，包含所有可配置选项。

### 3. 补丁生成器
- `generate-customer-patch.sh` - Linux/Mac 版本
- `generate-customer-patch.bat` - Windows 版本

### 4. 使用指南 (CUSTOMER-GUIDE.md)
详细的客户定制化使用文档。

## 快速开始

### 为新客户创建补丁包

1. **创建配置文件**
   ```bash
   cp tecon-patch/config-template.json tecon-patch/customer-new.json
   ```

2. **编辑配置**
   ```json
   {
     "customer": {
       "name": "新客户",
       "version": "1.3.1-new",
       "supportQQ": "123456789"
     },
     "features": {
       "stardust": {
         "enabled": true,
         "server": "http://your-server:6600",
         "appName": "FUXA-New"
       }
     }
   }
   ```

3. **生成补丁包**
   ```bash
   cd tecon-patch
   ./generate-customer-patch.sh customer-new.json
   ```

4. **添加品牌标识**
   ```bash
   cp new-logo.svg tecon-patch-新客户/logo.svg
   cp new-favicon.ico tecon-patch-新客户/favicon.ico
   ```

5. **打包分发**
   ```bash
   tar -czf tecon-patch-新客户.tar.gz tecon-patch-新客户
   ```

## 客户使用补丁包

### Windows 系统
1. 解压补丁包到 FUXA 根目录
2. 双击运行 `tecon-patch-客户名称\apply-patch.bat`
3. 按照提示执行构建命令

### Linux/Mac 系统
1. 解压补丁包到 FUXA 根目录
2. 执行 `./tecon-patch-客户名称/apply-patch.sh`
3. 按照提示执行构建命令

## 配置选项说明

### 功能开关
每个功能都可以独立启用或禁用：
- `enabled: true` - 启用该功能
- `enabled: false` - 禁用该功能

### 客户信息
- `name`: 客户名称（用于生成补丁包目录名）
- `version`: 客户版本号（用于版本管理）
- `supportQQ`: 技术支持联系方式

### Stardust 配置
- `server`: 星尘服务器地址
- `appName`: 应用名称（在星尘控制台显示）

### 地图源配置
- `url`: 地图瓦片服务器地址

### GitHub Actions 配置
- `branch`: 触发构建的分支名

## 批量管理

### 批量生成补丁包

创建批量生成脚本 `batch-generate.sh`：

```bash
#!/bin/bash
for config in tecon-patch/customer-*.json; do
    echo "处理配置: $config"
    cd tecon-patch
    ./generate-customer-patch.sh "$(basename $config)"
    cd ..
done
```

### 批量更新

当基础补丁包更新后，重新为所有客户生成补丁包：

```bash
./batch-generate.sh
```

## 故障排除

### 常见问题

1. **配置文件格式错误**
   - 检查 JSON 语法
   - 确保使用 UTF-8 编码

2. **补丁包生成失败**
   - 检查基础补丁包完整性
   - 确认有足够的磁盘空间

3. **客户应用补丁失败**
   - 检查 FUXA 版本兼容性
   - 确认文件权限

4. **功能不生效**
   - 检查配置文件中的 `enabled` 字段
   - 验证相关依赖是否安装

5. **S7 插件加载失败**
   - **现象**: `"try to create S7-1500 but plugin is missing!"`
   - **原因**: Node.js 版本不匹配或原生模块未正确打包
   - **解决方案**:
     - 使用 Node.js 18 进行打包
     - 确保打包命令包含 `--public-packages "node-snap7,bindings,nan"` 参数
     - 打包时 Node.js 版本必须与目标平台版本一致

6. **fontkit 编码错误**
   - **现象**: `RangeError [ERR_ENCODING_NOT_SUPPORTED]: The "windows-1252" encoding is not supported`
   - **原因**: fontkit 模块在 pkg 打包环境下不兼容
   - **解决方案**:
     - 从 `server/package.json` 中移除 `fontkit` 依赖
     - 从 `server/api/resources/index.js` 中移除 fontkit 引用

### 版本兼容性注意事项

| 目标平台 | 推荐 Node.js 版本 | 说明 |
|----------|------------------|------|
| node18-win-x64 | 18.x | S7 插件已预编译支持 |
| node20-win-x64 | 20.x | 需要重新编译 node-snap7 |

**关键原则**: 打包时 Node.js 版本必须与 `--targets` 参数指定的版本一致。
