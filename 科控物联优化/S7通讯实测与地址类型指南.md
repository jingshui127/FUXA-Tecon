## 二、区域与地址格式

| 区域 | FUXA 枚举 | 语义 | 读取通道 | 地址示例 |
|---|---|---|---|---|
| DB 数据块 | `S7AreaDB` | 工艺数据、配方、状态字 | `DBRead` 整块 | `DB1.DBX0.0`、`DB1.DBB0`、`DB1.DBW0`、`DB1.DBD194` |
| 输入映像 I | `S7AreaPE` | 传感器、按钮 | `ReadArea`（合并读） | `IW64` |
| 输出映像 Q | `S7AreaPA` | 接触器、指示灯 | `ReadArea`（合并读） | `QW64` |
| 位存储 M | `S7AreaMK` | 中间变量、启停标志 | `ReadArea`（合并读） | `MW100` |
| 定时器/计数器 T/C | `S7AreaTM`/`S7AreaCT` | 定时、计数 | — | 模拟器不支持 |

**地址解析规则**（`_getTagItem`）：

- 统一 `toUpperCase()` 并去空格，`db1.dbw0` 等价 `DB1.DBW0`。
- Bool 必须带位号 `DB1.DBX0.0`（字节.位）。只写 `DB1.DBX0` 时解析返回 null，标签静默失效。
- `type` 必须与地址长度匹配：Word 配 `DBW`、Real/DWord 配 `DBD`、Bool 配 `DBX`。

## 三、数据类型与长度

| FUXA type | S7 类型 | 长度 | node-snap7 WordLen |
|---|---|---|---|
| `BOOL` | 位 | 1 bit | `S7WLBit` |
| `BYTE` | 字节 | 1 B | `S7WLByte` |
| `WORD` | 字 | 2 B | `S7WLWord` |
| `INT` | 整数 | 2 B | `S7WLWord` |
| `DINT`/`DWORD` | 双字 | 4 B | `S7WLDWord` |
| `REAL` | 实数 | 4 B | `S7WLDWord` |

`datatypes.js` 中 `bytes` 属性决定整块读的区间长度；`parser(buffer, offset, bit)` 中 `bit` 仅 `BOOL` 使用（`-1` 表示返回整字节）。

## 四、驱动读写路径

| 路径 | 函数 | 通道 | 说明 |
|---|---|---|---|
| 读 DB | `_readDB` | `DBRead` | 按最小 `[offset, offset+size)` 单块读，再按偏移解析 |
| 读非 DB | `_readVars` | `ReadArea`（合并读） | 按 `(Area, DBNumber)` 分组整块读，再按偏移解析 |
| 写 DB | `_writeDB` | `DBWrite` | 单值整块写 |
| 写非 DB | `_writeVars` | `WriteMultiVars` | 位地址用 `Start*8 + bit` |

轮询：`polling()` 用 `Promise.allSettled` + `MAX_MIX_ITEM = 20` 分块，单块失败不影响其他块。`_updateVarsValue` 对 `BOOL` 用 `_getBit(value, bit)` 从整字节提取位。

## 五、地址类型实测矩阵

| 区域 | 类型 | 实测结果 |
|---|---|---|
| DB 区（DB1/DB2/DB3） | 位 / 字节 / 字 / 双字 / 实数 | ✅ 全部稳定（走 `DBRead`） |
| M / I / Q 区 | Word | ✅ 稳定 |
| M / I / Q 区 | 位 | ⚠️ 旧 `ReadMultiVars` 读错位；合并读后正确 |
| M / I / Q 区 | 字节 / 双字（多条批量） | ⚠️ 旧 `ReadMultiVars` 奇数索引项被拒；合并读后正确 |
| TM / CT | 定时器 / 计数器 | ❌ 模拟器不支持该区域 |
| 不存在的 DB（如 DB4、DB100） | — | ❌ `0xC00000` 对象不存在 |

**推荐用法**：DB 区放全部类型（工艺量、位、配方）；M/I/Q 区优先 Word；位与双字若走非 DB 区，需确认驱动为合并读版本。

## 六、已知缺陷与合并读方案

### 缺陷 1：非 DB 区位标签读错位

`_getTagItem()` 对 M/I/Q 位返回 `{Start: 字节地址, bit: 位}`，未乘 8 加 bit；而 `ReadMultiVars` 的 `S7WLBit` 要求 `Start` 为**位地址**。写路径 `_writeVars()` 做了 `Start*8 + bit`，**读写不对称**。

复现：预写 `M0=12`（`0b1100`），`M0.2`/`M0.3` 应为 1，实际读到 0。

### 缺陷 2：ReadMultiVars 多条奇数索引项被 CPU 拒绝

node-snap7 `ReadMultiVars` 对多条 `BYTE`/`BOOL`/`DWORD` 请求时，第 2、4、6…项返回 `Result=0x2300000`（function refused by CPU）；仅 `S7WLWord` 正常。DB/I/Q/MK 全部复现，属 node-snap7 通用问题。DB 区走 `DBRead`，不受影响。

### 修复方案：合并读

`_readVars` 改为按 `(Area, DBNumber)` 分组，用 `ReadArea` 整块读最小字节区间，再按偏移解析。与 DB 区 `_readDB` 语义一致，同时绕开缺陷 2，位标签也读到正确位。

```javascript
var _readVars = function (vars) {
    return new Promise((resolve, reject) => {
        if (!s7client) return reject(new Error('S7 client disconnected'));
        var groups = {};
        vars.forEach(v => {
            var key = (v.Area || 0) + '|' + (v.dbnum || 0);
            if (!groups[key]) groups[key] = [];
            groups[key].push(v);
        });
        var tasks = Object.keys(groups).map(key => {
            var items = groups[key];
            var area = items[0].Area;
            var dbnr = items[0].dbnum || 0;
            var minStart = Number.MAX_SAFE_INTEGER;
            var maxEnd = 0;
            items.forEach(v => {
                var len = (datatypes[v.type] && datatypes[v.type].bytes) ? datatypes[v.type].bytes : 1;
                if (v.Start < minStart) minStart = v.Start;
                if (maxEnd < v.Start + len) maxEnd = v.Start + len;
            });
            var size = maxEnd - minStart;
            return new Promise((res, rej) => {
                try {
                    s7client.ReadArea(area, dbnr, minStart, size, s7client.S7WLByte, (err, buf) => {
                        if (err) return rej(_getReadErr(err));
                        items.forEach(v => {
                            var off = v.Start - minStart;
                            var value = null;
                            try {
                                if (v.type === 'BOOL') {
                                    // 读整字节，由 _updateVarsValue 按 bit 提取
                                    value = datatypes['BYTE'].parser(buf.slice(off, off + 1));
                                } else {
                                    value = datatypes[v.type].parser(buf.slice(off, off + (datatypes[v.type].bytes || 1)));
                                }
                                v.changed = value !== v.value;
                                v.value = value;
                            } catch (e) { }
                        });
                        res();
                    });
                } catch (e) {
                    rej(_getReadErr(e));
                }
            });
        });
        Promise.all(tasks).then(() => resolve(vars), reason => reject(reason));
    });
}
```

**注意**：`datatypes[...].parser(buf.slice(...))` 的第二参数是 offset，默认 0；不要传 `-1`（`-1` 是 `_readDB` 里 `BYTE` 的位参数语义，用于整块读时返回整字节）。
