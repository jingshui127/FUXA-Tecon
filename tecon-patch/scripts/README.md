# PLC Tag 转换脚本说明

## 📂 文件结构

```
FUXA-master/
├── generate-csv.js          # Excel → CSV 转换脚本（核心）
├── clean-and-import-all.js  # CSV 清洗 + FUXA API 导入脚本
├── create-kaihemo-views.js  # 开合模参数监控画面生成脚本
├── new260429(1).xls         # 源 Excel HMI 地址表
├── plc-tags-D0.csv ~ D7.csv # 生成的标签 CSV 文件
└── tecon-patch/
    └── scripts/
        └── README.md        # 本文档
```

## 📋 脚本说明

### 1. `generate-csv.js` — Excel → CSV 转换

**功能**: 将 `new260429(1).xls` 中的 HMI 地址表转换为 Modbus 标签 CSV 文件。

**依赖**: `npm install xlsx`

**运行**:
```bash
node generate-csv.js
```

**输出**: 每个工作表生成对应的 `plc-tags-{sheetName}.csv` 文件。

---

### 2. `clean-and-import-all.js` — 清洗 + 导入 FUXA

**功能**: 读取所有 `plc-tags-D*.csv` 文件，过滤占位变量，批量导入到 FUXA 服务器。

**运行**:
```bash
node clean-and-import-all.js
```

---

### 3. `create-kaihemo-views.js` — 开合模参数监控画面生成

**功能**: 根据 PLC 标签自动生成 FUXA 组态视图，采用紧凑表格布局。

**运行**:
```bash
node create-kaihemo-views.js
```

**输出**: 两个页面 (1280×960)

| 页面 | 内容 | 参数数 |
|------|------|--------|
| 开合模参数 | 合模/开模表格 + 调模 + 功能 + 状态栏 | ~48 |
| 斜率/PID | 合模/开模斜率表 + PID参数 + 状态信号 | ~47 |

**布局特点**:
- **表格式布局**: 行=压力/速度/位置，列=各阶段，类似 Excel 表格
- **紧凑设计**: 相比分组列表布局节省 ~50% 空间
- **禁用格显示**: 未分配的段显示灰色背景 (null cells)
- **单位标注**: 行标题带单位 `[bar]` / `[%]` / `[mm]`
- **状态栏**: 底部一行显示关键状态值

**依赖**: FUXA 服务器需已导入标签数据 (先运行 clean-and-import-all.js)

## 🔄 Excel → CSV 转换规则

### Excel 数据格式

源 Excel (`new260429(1).xls`) 是注塑机 HMI 地址表，每个工作表对应一个数据区 (D0~D7)。

**单元格布局规则（用户确认）**:
```
[HMI地址 D####] [变量名/标签(1-2格)] [下一个 HMI地址] ...
```

- HMI 地址格式: `D0001`, `D0002`, ...
- 地址右侧紧跟着变量名/类型，可能占 1~2 格
- **如果地址右侧 1~2 格全部为空 → 该地址未分配变量，跳过**

### 类型识别

| Excel 类型文本 | 含义 | Modbus 寄存器数 | FUXA 类型 |
|---------------|------|----------------|-----------|
| `压力1`, `流量1`, `时间1`, `计数1` 等 | 单字变量 | 1 字 (16-bit) | **UInt** |
| `位置1`, `开始位置1` 等 | 双字变量 | 2 字 (32-bit) | **Int32** (Int32MLE) |
| `设定1`, `上限1`, `下限1` 等 | 设定值 | 1 字 | **UInt** |

**核心规则**: 只有类型文本包含「位置」的才是 2 字 Int32，其余一律 1 字 UInt。

### 变量命名规则

变量名 = `区域标签` + `类型后缀`

例如 Excel 中:
```
D0125 | "合模高压" | "压力1"  →  合模高压压力1
D0126 | --- | "流量1"          →  合模高压流量1  (区域标签继承)
D0127 | --- | "位置1"          →  合模高压位置1  (Int32, 2字)
D0128 | --- | ---              →  跳过(未分配)
D0129 | --- | "时间1"          →  合模高压时间1  (UInt, 1字)
```

### 地址映射

| 概念 | 示例 |
|------|------|
| HMI 地址 (Excel) | `D0129` |
| Modbus 地址 (0-based) | `4x0129` |
| FUXA 地址 (1-based) | `4X130` |

FUXA 使用 1-based 地址（比 HMI 地址大 1）。

## ⚠️ 已知问题及修复历史

### 问题 v1: 幽灵占位变量 (已修复)

**现象**: `合模高压时间1_1` 到 `合模高压时间1_5` 等无实际意义的变量被生成。

**根因**: 旧版脚本的「继承逻辑」将未分配地址（右侧全空）错误地填充了前一个变量的名称，导致生成大量 `_N` 后缀的幽灵条目。

**修复 (v2)**: 
- 删除继承逻辑
- 地址右侧无任何数据 → 直接跳过
- 字数由类型决定，而非合并相邻地址

### 问题 v2: 时间变量错误标记为 Int32 (已修复)

**现象**: `合模高压时间1` 被标记为 `Int32, 2字`，实际应为 `UInt, 1字`。

**根因**: 旧版合并逻辑对任何连续同名地址都合并为 2 字。

**修复 (v2)**: 只有「位置」类型用 2 字 Int32，其余一律 1 字 UInt。

## 🔧 如何重新生成 CSV

1. 确认 `new260429(1).xls` 在项目根目录
2. 运行: `node generate-csv.js`
3. 检查输出日志，确认各工作表标签数
4. 如需导入 FUXA: `node clean-and-import-all.js`

---

## 📝 FUXA 导入注意事项

- 导入前确保 FUXA 服务器已启动
- 设备配置 (`modbus` 设备) 需要正确的 PLC IP 地址
- 如果 FUXA 地址或 API Key 变更，手动修改 `clean-and-import-all.js` 中的配置
- 使用 FUXA Skill (`fuxa-automation`) 可以交互式管理导入流程
