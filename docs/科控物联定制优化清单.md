### 3. S7 稳定性

- [x] 断开连接时避免调用可能触发 native 冲突的底层 `Disconnect()`。
- [x] 连续异常或 overload 后清理旧客户端并强制全新重连。
- [x] 读取变量、读取 DB 和获取错误信息前增加客户端状态保护。
- [x] 进程退出时清理 S7 客户端引用，降低 native 清理冲突。
- [x] 读取路径改为合并读（2026-11-06）：非 DB 区（M/I/Q）不再走 `ReadMultiVars`，改为按 `(Area, DBNumber)` 分组用 `ReadArea` 整块读最小字节区间后按偏移解析，与 DB 区 `_readDB` 语义一致。
- [x] 补齐 `_getReadErr`（连接丢失判定），与普通版保持一致。
- [x] **nodes7 插件注册与 snap7 回退（2026-11-27，提交 `325d9a02`）**：
  - `server/runtime/plugins/index.js` 注册 `nodes7` 为 `SiemensS7` 类型插件，解决 PRO headless 未打包 `node-snap7` 时设备类型下拉空白的问题。
  - `server/runtime/devices/s7/index.js create()` 在设备显式 `driver:"snap7"` 但 native 包不可用时回退 `nodes7`，日志输出 `[s7] node-snap7 not available, using nodes7 driver`。
  - 新 EXE 实测：`/api/plugins` 同时显示 `node-snap7 1.0.9` 与 `nodes7 0.3.18`；Bool `0→1`、Real `0→12.5` 写入成功。

## 五、明确不再作为当前方案的内容

以下内容属于历史方案，不应直接照搬：

- 旧版本 `1.3.1` 的绝对路径和部署目录。
- 手工直接修改已编译 JS 文件作为日常地图或品牌维护方式。地图瓦片必须走 `server\scripts\patch-map-tiles.js`（打包时自动替换并校验 `[patch-map] verification passed`），品牌必须走 `docs\customization\`，不得手工改 `client\dist`。
- 在 `server` 目录中手工重复安装网页通讯插件作为默认流程。
- 旧版 `FuxaPro-Single.exe` 等非当前正式产物名称。
- 将 `/nodered` 当作当前主要管理入口。
- 将运行时 `data\\`、`artifacts\\` 或临时构建目录纳入源码提交。
- 仅执行 `npm ci` 或仅复制文件后就认定 EXE 已完成构建。
