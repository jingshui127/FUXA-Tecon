# FUXA 品牌配置说明（操作手册）

> **这份文档给「要改品牌的人」看**：放哪、写什么、怎么生效、怎么验证、怎么回退。
> 想改源码实现或查改造原因 → `FUXA定制化优化指南.md §2.12`；维护者速查 → `skills/fuxa-maintainer/SKILL.md`。
> 版本：`1.3.6-2919`，2026-11-16 按 `server/brand.js` 实际代码逐条核对（2919 仅版本号 bump，`brand.js` 未改动）。

**一句话**：改 `data/brand.json` + 放两个图片 → 重启 FUXA → 浏览器强刷。**既不用重新构建前端，也不用重新打包 EXE。**

---

## 一、配置文件放哪里

`brand.json` 会被逐个目录找，**取第一个存在的**：

| 优先级 | 路径 | 典型场景 |
|:--:|---|---|
| 1 | `<EXE 所在目录>/data/brand.json` | **EXE 部署，推荐** |
| 2 | `<EXE 所在目录>/brand.json` | EXE 部署，备用 |
| 3 | `<rootDir>/brand.json` | 源码模式 = `server/brand.json` |
| 4 | `<rootDir>/data/brand.json` | 源码模式 = `server/data/brand.json` |
| 5 | `<rootDir>/../data/brand.json` | 源码模式 = 仓库根 `data/`（**本仓库当前就在这**） |
| 6 | `<rootDir>/../brand.json` | 仓库根 |

> `rootDir` 默认是 `__dirname`（源码模式即 `server/`；**EXE 模式下是 pkg 快照内的只读路径**），可用命令行 `--userDir` 或环境变量 `process.env.userDir` 覆盖。所以：
> - **EXE 部署只有第 1、2 条真正可改**——打进包里的配置改不动；
> - **源码开发用的是第 5 条**：`FUXA-Tecon-Normal/data/brand.json`。
> 启动日志里会打印**实际读到的那一个完整路径**，别猜。

目录结构（当前版本）：

```
FUXA-1.3.6-2919/
├── FUXA-1.3.6-2919-win-x64.exe
└── data/
    ├── brand.json          ← 品牌配置
    ├── logo.svg            ← 品牌 Logo
    ├── favicon.ico         ← 浏览器图标
    ├── _appdata/           ← 工程与运行数据
    └── _reports/           ← 生成的 PDF 报表
```

**都没找到时**：再去找 PRO 版格式 `customization/config.json`（见第五节），仍没有就走 FUXA 默认品牌。

## 二、写什么

当前仓库实际使用的配置（`FUXA-Tecon-Normal/data/brand.json`）：

```json
{
    "name": "TcScada",
    "title": "科控物联 - 工业监控平台",
    "logo": "logo.svg",
    "favicon": "favicon.ico",
    "shortName": "KKWL",
    "footer": "© 2026 科控物联"
}
```

| 字段 | 类型 | 必填 | 说明 | 影响位置 |
|---|:--:|:--:|---|---|
| `name` | string | ✅ | 品牌名称，默认 `FUXA` | 侧边栏标题、加载页 `{name} Loading...`、关于对话框标题 |
| `title` | string | — | 浏览器标签页标题，默认 `FUXA` | `<title>` |
| `logo` | string | — | 文件名 或 **http(s) 绝对 URL**；`null` 表示不用图片 | 加载页、关于对话框、侧边栏（用户未自定义布局 Logo 时回退） |
| `favicon` | string | — | 文件名 或 **http(s) 绝对 URL** | `<link rel="icon">` |
| `shortName` | string | — | 短名称，默认同 `name`；**当前无任何组件使用**，仅接口保留 | 无（预留） |
| `footer` | string | — | 页脚文字，默认空 | 加载页底部、关于对话框底部、用户信息对话框底部、**PDF 报表 header** |

**图片文件找法**：先看 `brand.json` **所在目录**，再看同目录下的 `customization/`。

- 支持 PNG / JPG / SVG / ICO；Logo ≤ 500 KB，favicon ≤ 100 KB。
- 也可以直接写 URL（`"logo": "https://cdn.example.com/logo.png"`），此时不走本地文件。
- **没配 logo 但改了 name**：加载页显示品牌首字母（蓝底方块），不会露出 FUXA 图标。
- 图片没配或文件找不到时，`/api/brand/logo`、`/api/brand/favicon` 直接返回 **404**，前端各位置回退默认样式（不会裂图）。
- `window.__BRAND__` 里只有 `name / title / logo / shortName / footer`，**没有 favicon**——favicon 是服务端直接改 `<link>`，不经过前端。

## 三、覆盖到哪里（含尚未覆盖的）

| 位置 | 取值 |
|---|---|
| 浏览器标签页 | `title` |
| 浏览器图标 | `favicon` |
| 加载页 Logo / 文案 / 底部 | `logo` / `{name} Loading...` / `footer` |
| 侧边栏标题与 Logo | `name` / `logo` |
| 编辑器「关于」对话框 | Logo + `name` + `footer` |
| 用户信息对话框底部 | `footer` |
| PDF 报表 header | `footer` |

**残留与已修（2026-11-16 二次核查）**：

| 位置 | 状态 | 说明 |
|---|---|---|
| AR 视图标题 | ✅ **已修**（源码，待重打包） | 原 `ar-view.component.html:6` 写死 `FUXA AR`；现改为 `{{brandName}} AR`，读 `AppService.getBrandName()` |
| 邮件测试主题 | ✅ **已修**（源码，待重打包） | 原 `editor/app-settings/app-settings.component.ts:140` 写死 `'FUXA'`；现为 `{品牌名} TEST` |
| 登录页 | ⚪ **不改** | 原版登录框就没有品牌位。**现场未启用安全模式**（`AuthGuard` 要求 `isSecurityEnabled()` 或服务端 `secureEnabled`），登录框根本不会弹出；加品牌位属 UI 增强，非缺陷 |
| `index.html` 的 `FUXA Loading...` / `powered by frangoteam` | ⚪ **不是残留** | 模板里是死的，但 `brand.js:212-247` 运行时会换成 `{name} Loading...` / `footer`。**只有 `name=FUXA` 且 `footer` 为空时才露出原文** |
| `_models/device.ts` 的 `FuxaServer.name='FUXA'` | ⚪ **不改** | 设备列表里 id=0 的系统设备显示名。逻辑只按 `DeviceType.FuxaServer` / `id==='0'` 判定，name 纯显示；但改它只影响新建工程（已有工程存的是自己的 name），收益≈0 |
| `console.log('FUXA ...')` | ⚪ **不改** | 只在开发者控制台可见，非用户界面 |
| `repoName='FUXA-SVG-Widgets'` | 🔴 **禁止改** | 这是 GitHub 仓库名，改了 SVG 控件库直接拉不到 |

> 前两项是**前端源码**改动：必须重新构建前端并打包 EXE 才在现场生效（`client/dist` 未纳入 git，CI 每次打包都用 `npm run build --configuration=production` 从源码重建）。**不重打包 = 现场看不到变化，也不会变坏。**

## 四、生效与验证

品牌配置**在服务器启动时一次性读进内存**，改文件不会热更新。

1. 编辑 `data/brand.json`，放好 `logo.svg` / `favicon.ico`；
2. **重启 FUXA**（EXE 直接关掉再开，或 `-p <端口>` 重新起）；
3. 浏览器 `Ctrl + Shift + R` 强刷（favicon 缓存很顽固，必要时换浏览器或无痕窗口）。

启动日志的判据（没有这行说明没读到，走了默认品牌）：

```
[Brand] Loaded brand config from ...\data\brand.json: name="TcScada"
```

PRO 配置命中时是：

```
[Brand] Loaded customization config from ...\customization\config.json: name="TcScada"
```

四条验证，全过才算成功：

```bash
curl -s http://127.0.0.1:1882/api/brand          # 返回完整品牌 JSON（name/title/logo/favicon/shortName/footer）
curl -sI http://127.0.0.1:1882/api/brand/logo    # 200 + image/*
curl -sI http://127.0.0.1:1882/api/brand/favicon # 200 + image/*
curl -s http://127.0.0.1:1882/ | grep -o "window.__BRAND__=[^<]*"
```

再肉眼确认：标签页标题、标签页图标、侧边栏标题、F5 时加载页、编辑器「关于」、用户信息弹窗底部。

> PDF 报表 header 用的是 `footer`：改了之后**历史 PDF 不会变**，要重新生成（`POST /api/reportBuild`，body `{"params":{"id":"r_line2_daily"}}`）。

## 五、与 PRO 版共用一份配置

> **品牌母本（权威）**：`FUXA-Tecon-PRO\docs\customization\`（`config.json` + `logo.svg` + `favicon.ico`）。普通版不单独维护品牌文件，logo/favicon 以该母本为准，配置经下方映射复用。

`data/brand.json` 不存在时，会自动读 PRO 版 `customization/config.json` 并做映射：

| PRO 字段 | → 品牌字段 |
|---|---|
| `appName` / `sideMenuTitle` / `appInfo.title` | `name` |
| `appTitle` / `appInfo.title` | `title` |
| `splash.image` / `appInfo.image`（只取文件名） | `logo` |
| `favicon` | `favicon` |
| `splash.subText` / `appInfo.subText` | `footer` |

所以普通版和 PRO 版可以共用一份品牌配置，不用维护两套。**注意**：`brand.json` 优先级更高，两个都存在时 PRO 配置不生效。

## 六、回退

删掉（或改名）`brand.json` → 重启 → 自动回落默认品牌：`name/title/shortName = "FUXA"`、`logo = null`、`footer = 空`、favicon 用包内原版。不需要改代码或重新打包。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 改了没生效 | 没重启 / 没强刷 | 先看启动日志有没有 `[Brand] Loaded` |
| 改了生效一半（比如标题变了、Logo 没变） | 改了 EXE 目录那份，但实际生效的是 userDir 那份（或反之） | 按第一节顺序核对到底读的哪个，日志里有完整路径 |
| Logo 显示成裂图 | 文件名写错 / 不在 `brand.json` 同目录 / 写成了 `/logo.svg` 这种路径 | 只写文件名；要绝对路径就写完整 `http(s)://` URL |
| 中文变乱码或读取失败 | `brand.json` 存成了 GBK 或带 BOM | 存 UTF-8 无 BOM；解析失败时会回退默认并打 `[Brand] Failed to parse` |
| 换机器后品牌没了 | `brand.json` + 图片在 `data/` 里，只拷了 exe | 连 `data/` 一起拷（至少 `brand.json`、`logo.*`、`favicon.*`） |
| 分发给他人的 EXE 露出 FUXA | 对方 `data/` 里没有 `brand.json` | 见上一条；`data/` 是分发包的一部分 |

## 八、涉及的文件

| 文件 | 作用 |
|---|---|
| `data/brand.json` | 品牌配置（唯一需要日常改的文件） |
| `data/logo.svg`、`data/favicon.ico` | 品牌图片 |
| `server/brand.js` | 加载、查找目录、PRO 映射、HTML 注入 |
| `server/main.js` | 注册 `/api/brand`、`/api/brand/logo`、`/api/brand/favicon`（**均无需认证**） |
| `client/src/app/_services/app.service.ts` | `BrandConfig` 接口 + `getBrand()/getBrandName()/getBrandLogo()`，从 `window.__BRAND__` 读 |
| `client/src/app/sidenav/*` | 侧边栏标题 / Logo |
| `client/src/app/header/info.dialog.html` | 关于对话框 |
| `client/src/app/home/userinfo.dialog.html` | 用户信息对话框 |
| `client/src/app/reports/report-editor/report-editor.component.ts` | PDF 报表 header |

实现细节与改造原因见 `FUXA定制化优化指南.md §2.12`。
